# ADR-0010: SDD authoring — markdown + Mermaid + pandoc/xelatex

**Status:** Accepted
**Date:** 2026-06-03
**Drivers:** SDD is part of the end deliverable; must be diffable, queryable, and renderable to PDF; must live next to the code.

## Decision

The SDD is authored in **markdown** under `tta/docs/`. The main document is `SDD.md`; ADRs are numbered files under `adr/`; the user-story catalogue is `user-stories.md`; the bibliography is `references.bib` (BibTeX).

Diagrams are authored in **Mermaid**, inline in markdown fenced code blocks. GitHub/GitLab render them natively; pandoc renders them to PDF via a Node-based filter (`mermaid-filter`) or a pre-rendered SVG fallback.

The PDF render uses **pandoc + xelatex**:

```bash
pandoc docs/SDD.md docs/adr/*.md \
       -F mermaid-filter \
       --resource-path=.:docs/adr \
       --citeproc --bibliography docs/references.bib \
       --pdf-engine=xelatex \
       --toc --number-sections \
       -V documentclass=scrartcl \
       -V geometry:margin=2.5cm \
       -o sdd.pdf
```

## Conventions

- Internal cross-references use markdown links; section anchors are autogenerated by pandoc from headings.
- Citations are pandoc-style `[@key]` against entries in `references.bib`.
- Inline math uses `$…$`; block math `$$…$$`.
- Images referenced by an ADR live next to it in `docs/adr/`, named with the ADR's number and slug (`0021-image-counting-image-sizes.png`), and are linked relatively from the ADR. pandoc resolves image paths against `--resource-path`, not the markdown file's directory, hence `docs/adr` in the command above (2026-10-14, #85).
- LaTeX-only constructs (raw `\textrightarrow{}`, etc.) are permitted but discouraged; prefer Markdown / Mermaid first.
- ADRs follow a consistent template (Status, Date, Drivers, Decision, Context, Alternatives, Consequences, Revisit).

## Alternatives considered

- **LaTeX source.** Heavier tooling, less diffable, larger barrier to entry. Rejected.
- **AsciiDoc / reStructuredText.** More features than markdown but less universal. Rejected.
- **Notion / Confluence.** Not version-controllable next to code. Rejected.
- **PlantUML for diagrams.** Native rendering in GitHub is weaker, separate `.puml` files clutter the repo. Rejected in favour of Mermaid.

## Consequences

- ✅ One toolchain (pandoc) we already know from prior project work.
- ✅ Documents diff cleanly in code review.
- ✅ GitHub previews are first-class — open `SDD.md` on github.com, diagrams render, ADRs are clickable.
- ✅ PDF render path is well-understood from prior project work.
- ⚠️ Mermaid filter requires Node + Chromium at render time. Pre-rendering SVGs is the fallback when that's unavailable.
- ⚠️ Math in markdown sources must be xelatex-clean; we adopt the same conventions used in the project's prior slide decks.

## Revisit when

If the SDD grows past ~50 pages and starts to suffer from markdown's limitations (cross-document references, indexed terms, etc.), AsciiDoc becomes a reasonable consideration.
